# Writing documentation

User guides explain tasks/outcomes, developer guides explain contracts, plans/research retain assumptions/evidence. Distinguish implemented, automated-tested, native-observed and externally gated behavior.

Update an existing topic before duplicating guides. Link maintained modules and real scripts. Label HTTP/SQLite/sync recipes as future extensions. Keep historical commands historical.

Use concrete examples and short paragraphs. Add translations consistently. Do not invent support contacts/response promises. User-visible commands need guide updates; cross-platform compilation is not runtime acceptance.

Check local links/commands, update indexes/parity, and verify snippets against installed APIs. The userguide-reviewer role recommends updates without rewriting unless authorized.
