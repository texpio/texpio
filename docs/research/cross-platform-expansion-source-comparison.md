# Cross-platform expansion: Espanso and Snipt source comparison

24 October 2026 · Static source analysis, linked to the current Windows failure

## Findings

Use Espanso as the primary reference for platform boundaries, application-specific insertion policy and operational experience. Snipt is also a system-wide text expander: its daemon captures global events through `rdev` and injects through `enigo`. Its smaller wrapper is useful to inspect, but its inspected source does not establish reliable support on every advertised platform. Neither project proves that a submitted keystroke reached the intended control or produced the exact replacement.

For Texpio, retain the shared Rust matcher/render pipeline and implement four independently qualified adapters: Windows, macOS, Linux/X11 and Linux/Wayland. Keep Tauri/React/shadcn as the management UI. Our existing suffix/caret, target identity, cancellation and observed-output guarantees remain requirements; adopting another project's keyboard-history deletion behavior would change the product contract.

No upstream application, installer, permission helper or test suite was run. The references were cloned/read under ignored `.superpowers/reference`; no upstream runtime code was copied into Texpio and no product dependencies were changed.

## Source details that matter for correctness

### Espanso: useful separation, different guarantees

Espanso separates trigger compensation, rendering, key injection, text injection and clipboard injection. Its [text strategy selector](https://github.com/espanso/espanso/blob/a87d1723f47a59e38d370e2f0c636d66d568b8f6/espanso-engine/src/dispatch/executor/text_inject.rs#L66) chooses event or clipboard insertion before executing the effect; automatic policy considers length and, on Linux, ASCII representability. This is useful architecture for an explicit selected backend. It is not a reason to retry through the clipboard after an uncertain keyboard insertion.

The Windows native `inject_string` already builds one array of paired Unicode press/release events and calls `SendInput` once. The Rust Windows `send_string` ignores `InjectionOptions`; a configured text delay therefore does not pace individual Windows Unicode characters in this implementation. Key/combination injection has separate delayed variants. This distinction rules out treating a generic upstream delay setting as a demonstrated fix for our current Windows failure. See the [native implementation](https://github.com/espanso/espanso/blob/a87d1723f47a59e38d370e2f0c636d66d568b8f6/espanso-inject/src/win32/native.cpp#L42) and [Rust wrapper](https://github.com/espanso/espanso/blob/a87d1723f47a59e38d370e2f0c636d66d568b8f6/espanso-inject/src/win32/mod.rs#L75).

Its [event adapter](https://github.com/espanso/espanso/blob/a87d1723f47a59e38d370e2f0c636d66d568b8f6/espanso/src/cli/worker/engine/dispatch/executor/event_injector.rs#L47) splits lines and emits Return between them. Our current literal LF contract is different and remains unqualified in native Notepad. A profile-specific line-ending strategy needs exact output tests, rather than copying the upstream behavior without changing the expected contract.

Espanso's native Windows wrapper does not check the returned submission count, and its common path does not observe an exact resulting target string. Its [clipboard restoration guard](https://github.com/espanso/espanso/blob/a87d1723f47a59e38d370e2f0c636d66d568b8f6/espanso/src/cli/worker/engine/dispatch/executor/clipboard_injector.rs#L181) restores a saved text value after a delay. It does not establish preservation of every clipboard format or concurrent-copy ownership. Texpio should retain stronger outcome and clipboard guarantees.

### Snipt: concrete limitations in the inspected tree

- The exported `execution` module imports `std::os::unix::fs::PermissionsExt` without a platform guard. This is a concrete native-Windows portability gap in this tree; Snipt was not built here to turn that static observation into a build result. Its inspected build/release matrices cover Linux/macOS, despite the README's Windows badge. Sources: [module](https://github.com/snipt/snipt/blob/dc5476049d3d0470c2c3685da3db6e62a71524bf/crates/snipt-core/src/execution.rs#L5), [exports](https://github.com/snipt/snipt/blob/dc5476049d3d0470c2c3685da3db6e62a71524bf/crates/snipt-core/src/lib.rs#L4), [CI](https://github.com/snipt/snipt/blob/dc5476049d3d0470c2c3685da3db6e62a71524bf/.github/workflows/build.yml), [release matrix](https://github.com/snipt/snipt/blob/dc5476049d3d0470c2c3685da3db6e62a71524bf/.github/workflows/release.yml#L88).
- `rdev_key_to_char` accepts regular event names only when `name.len() == 1`, measuring UTF-8 bytes. A name such as `é` is one Unicode scalar but multiple bytes and is rejected by this path. The listener passes string `.len()` values to counted Backspaces. These are unsuitable general Unicode recognition/deletion semantics. Sources: [conversion](https://github.com/snipt/snipt/blob/dc5476049d3d0470c2c3685da3db6e62a71524bf/crates/snipt-core/src/keyboard.rs#L44), [listener](https://github.com/snipt/snipt/blob/dc5476049d3d0470c2c3685da3db6e62a71524bf/crates/snipt-daemon/src/keyboard_listener.rs#L132).
- Matching/expansion is performed synchronously inside the grabbed-event callback while holding shared mutexes. Expansion errors are discarded at several call sites, and the shown buffer path has no exact current suffix/caret/password validation. Returning `None` suppresses an event through rdev. Keep our hook callback small, queue native work, preserve origin markers and generations, and render before deleting. Source: [listener](https://github.com/snipt/snipt/blob/dc5476049d3d0470c2c3685da3db6e62a71524bf/crates/snipt-daemon/src/keyboard_listener.rs).
- Its [replacement helper](https://github.com/snipt/snipt/blob/dc5476049d3d0470c2c3685da3db6e62a71524bf/crates/snipt-core/src/expansion.rs#L497) sends Backspaces, waits, then types lines/chunks through Enigo. Those sleeps express a compatibility choice; they are not target acknowledgement, cancellation or measured evidence for Texpio's failing case.
- The pinned Enigo Linux implementation attempts both Wayland and X11 connections and sends text/keys through each connection that exists. **Inference:** in a mixed session, duplicate delivery or delivery into a different backend's focused target is a risk worth testing. This is not proof that every mixed desktop exhibits it. Texpio should choose one backend per job. Sources: [connection setup](https://github.com/enigo-rs/enigo/blob/7b2387f88fdb35f40e71099c1a6929af67ff8dc2/src/linux/mod.rs#L55), [dispatch](https://github.com/enigo-rs/enigo/blob/7b2387f88fdb35f40e71099c1a6929af67ff8dc2/src/linux/mod.rs#L299).
- Snipt's Wayland application-context helper explicitly returns an empty name. Its Windows helper launches a separate PowerShell process and queries that process's Windows Forms `ActiveForm`; it does not identify an arbitrary foreground application's native HWND. Neither is sufficient target evidence for our contract. Source: [context helpers](https://github.com/snipt/snipt/blob/dc5476049d3d0470c2c3685da3db6e62a71524bf/crates/snipt-core/src/expansion.rs#L112).

Snipt and these two dependencies identify their licenses as MIT. Espanso's audited source identifies GPL-3.0-or-later. See the [Snipt license](https://github.com/snipt/snipt/blob/dc5476049d3d0470c2c3685da3db6e62a71524bf/LICENSE) and [Espanso license](https://github.com/espanso/espanso/blob/a87d1723f47a59e38d370e2f0c636d66d568b8f6/LICENSE). This report describes mechanisms and links sources; it does not select Texpio's product license or port licensed runtime code.

## Applying the findings to the current failure

The [current acceptance record](offline-mvp-acceptance.md) contains the native evidence. The greeting trial fully submitted 52/52 events but did not produce the expected output. An accented case fully submitted 42/42 and also failed exact verification. After the user shut TextExpander down, zero TextExpander processes were verified, and a fresh greeting fixture still failed after 52/52 submission. TextExpander alone therefore does not explain the failure.

Both upstream Windows text implementations use paired UTF-16 Unicode events. Espanso and Snipt separate deletion from text injection; Texpio currently combines verified deletion and Unicode output in one batch. That is a specific experimental difference, not an established root cause. No batching change was made to the product.

An explicit [owned Win32 receiver](../../src-tauri/examples/unicode_receiver_trial.rs) subsequently submitted the same 52-event deletion/output sequence to its own EDIT control. It received 19 exact Unicode `WM_CHAR` values and observed the exact 19-unit replacement after deletion. The diagnostic window was destroyed and the helper exited; no global hooks were installed. An initial harness caret-offset error was corrected before this full-replacement result. This narrows investigation toward Notepad/control-specific processing; it does not identify the precise failing component or qualify every Win32 application. Further isolation should compare control behavior and vary one factor at a time. Never repair or replay an uncertain edit in a user document.

## Implementation and qualification priorities

1. Finish Windows diagnosis using owned fixtures and exact requested/submitted/observed outcomes. Retain fail-closed target validation and explicit rearm after uncertainty.
2. Make one backend choice before mutation. Keep automatic clipboard insertion disabled until format preservation, ownership, cancellation and paste acknowledgement are qualified; explicit Copy already has separate native evidence.
3. Keep OS capture/layout/composition, target evidence, permissions and native effects behind capability-bearing adapters. The shared core owns bounded matching, immutable rules, rendering and cancellation generations.
4. Add macOS next, with real-Mac Accessibility/Secure Input, run-loop and Unicode tests. Implement X11 and Wayland independently afterward. Wayland needs a deliberate device-permission/compositor strategy rather than a generic Linux switch.
5. Publish a measured OS/backend/application/control matrix. Test emoji, combining sequences, Devanagari, RTL, IME commits, AltGr, dead keys, line endings, selections, focus/tab changes, held modifiers, concurrent copy, competing expanders and teardown on each declared platform. Static source inspection and synthetic checks do not complete physical qualification.

The approved Windows-first scope remains in force. No backend/sync service, universal compatibility mode or cross-platform release claim is introduced by this analysis.
